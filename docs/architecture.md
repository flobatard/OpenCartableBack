# Architecture du back — approfondissements

Ce document explique **pourquoi** le code est fait ainsi, paquet par paquet ; il complète le `CLAUDE.md` (commandes, carte, invariants) sans redire ce que les docstrings, les schémas et les tests disent déjà. Les codes HTTP exacts, les messages d'erreur et l'ordre des `execute` sont documentés dans le code (docstrings des services) et vérifiés par `tests/`.

## Auth et comptes

**Resource server pur** (`app/core/auth.py`). Le flow OIDC est entièrement porté par la SPA ; l'API valide le JWT Zitadel de chaque requête (signature RS256 via le JWKS découvert depuis l'issuer, vérification issuer/audience/expiration). Seuls réglages : `OIDC_ISSUER` et `OIDC_AUDIENCE` (= client id du front). Zitadel doit émettre des **JWT access tokens** (ses tokens opaques par défaut donnent 401). Sémantique : credentials absents ou token invalide → 401 + `WWW-Authenticate: Bearer` ; IdP injoignable ou discovery/JWKS malformé → 503 ; jamais de 500, jamais le token dans les logs. `GET /api/v1/me` (`app/system/`) est la route protégée de référence, `/health` reste publique.

**Comptes** (`app/users/`). La ligne `users` est **auto-provisionnée** au premier `GET /users/me` (upsert `ON CONFLICT DO NOTHING` sur `sub`, seule donnée IdP persistée, e-mail en snapshot). Le profil (`PUT /users/me/profile`) est un **remplacement complet** — il sert d'onboarding et d'édition ; rôles cumulables `is_teacher`/`is_student` ; les M2M `user_subjects`/`user_education_levels` sont qualifiées par `context` (`teaching`/`learning`) ; profil complet ⟺ `onboarded_at` non NULL. `public_name` (opt-in) est la seule identité exposée sur les pages publiques ; `searchable` (opt-in, défaut `False` — un PUT sans le champ « décoche ») ouvre l'annuaire des profs. Avatar : même flow presigned que les ressources, sous `users/<id>/avatar/`.

## Configuration

Priorité décroissante : variables d'env > `.env` > `config/<APP_ENV>.yaml` (`development` par défaut ; `preprod` et `production` existent). Les YAML portent les valeurs publiques versionnées (CORS, hôtes, OIDC, S3 endpoint/bucket/région, TTL, plafonds, délais de purge, provider IA par défaut) ; `.env` les secrets et overrides locaux (mot de passe Postgres, clés S3, clé API du fallback IA, clé maître de chiffrement, clés Langfuse). `DATABASE_URL` est assemblée depuis les `POSTGRES_*` (mot de passe percent-encodé) ; une URL complète collée prend le pas et est normalisée pour asyncpg (`sslmode`/`channel_binding` → `ssl=`). Tous les réglages ont un défaut : le conftest n'a rien à poser, mais `settings` s'évalue à l'import — les variables de test sont posées en tête de `tests/conftest.py`.

## Taxonomies

**Matières** (`app/subjects/`) : table auto-référencée (discipline → domaine → sous-domaine → sujet, profondeur flexible, CHECK en base), unicité `(parent_id, name)` en `NULLS NOT DISTINCT` (Postgres 15+). Chaque nœud porte un `code` = chemin slug complet (`mathematiques.algebre.algebre-lineaire`) dont dérive son id **uuid5 déterministe** : portable entre instances (export/import), stable entre déploiements. Le seed (~475 nœuds, lycée → master) est un module de données **APPEND-ONLY** : ne jamais changer `SEED_NAMESPACE` ni renommer un `code` ; tout ajout = nouvelle data migration réutilisant `iter_rows()`. Lecture : une seule requête, arbre assemblé en O(n) en Python (pas de relation ORM chargée).

**Niveaux d'étude** (`app/education_levels/`) : même motif, deux profondeurs (cycle > classe), un arbre par système scolaire (`system`), unicité `(system, parent_id, name)`. Les `code` sont écrits à la main et préfixés (`fr.college.6e`) ; les pivots internationaux `cite` (ISCED 2011) et `age_min`/`age_max` permettront de rapprocher des cours entre pays — les `name` sont des noms propres nationaux, jamais traduits. `SEED_NAMESPACE` propre, distinct de celui des matières.

Les deux arbres sont aussi servis sans JWT sous `/public/*/tree` (facettes de recherche).

## Modèle des cours et contrats JSONB

`courses` appartient à un user (`owner_id`, CASCADE), classé par deux M2M sans qualificatif (`course_subjects`, `course_education_levels`, PK composite `course_id` en tête + index inverse pour les facettes). `preview_settings` (JSONB, `{}` par défaut) porte les réglages de lecture du cours, contrat camelCase = interface `CourseStyleSettings` du front, remplacé en entier par `PUT /courses/{id}/preview` (six champs bornés, `extra="forbid"`) — ajouter un réglage = un champ Pydantic, sans migration. `visibility` ∈ `public`/`private`/`draft` (défaut ; CHECK posé à la main).

`blocks` : `position` sans unicité (le réordonnancement réécrit 0..n-1 ; tri stable `position, id`), `title`/`description` facultatifs communs, quatre types dont le `content` JSONB est le **contrat documenté dans `app/models/block.py`** et validé par les schémas `TextContent`/`ExerciseContent`/`DocumentContent` (union de formes disjointes, `extra="forbid"`) :

- `text` : `{"markdown"}` — jamais de HTML brut ; formules LaTeX, Mermaid, TikZ, GeoGebra, JSXGraph et liens `oc-resource:`/`oc-module:` vivent dans la chaîne, rendus par le front.
- `exercise` : `{"statement", "questions": [{id, statement, type, expected_answer}]}` — `expected_answer` = corrigé du prof en texte simple, jamais servi aux élèves ; les ids de questions sont générés en service et **stables à vie** (sémantique remplacement à l'édition : question absente = supprimée, id inconnu = 422).
- `document` : `{"caption", "display"}` + **colonne** `resource_id` (nullable, FK CASCADE, réservée à ce type par CHECK).
- `module` : `{}` + **colonne** `module_id` (idem). Le content d'un bloc module n'est pas éditable.

Un bloc pointeur meurt avec sa cible (FK CASCADE : supprimer une ressource ou un module supprime les blocs). Supprimer un bloc ne touche jamais ni `resources` ni S3. Toute mutation de bloc `touch(course)`.

Pièges Alembic : autogenerate ne détecte pas la modification d'un CHECK (élargir `ck_blocks_type` = migration manuelle) ni les données ; la FK `blocks.resource_id` créée sans nom s'appelle `blocks_resource_id_fkey` en base.

## Ressources S3

`app/core/storage.py` confine boto3 et expose la dépendance `get_storage` (overridable en test). Bucket **privé**, jamais exposé : l'upload est direct navigateur → S3 par URL présignée (on ne fait pas transiter les binaires par le backend, contrainte Pi), la lecture par presign GET à TTL court — dimensionné pour couvrir la lecture d'un PDF embarqué (le viewer natif fait des range requests au fil du scroll ; un TTL trop court coupe en 403). `presign_put`/`presign_get` sont du calcul local (appel sync OK dans un handler async) ; `head`/`delete_many`/`iter_objects` parlent au réseau, sous threadpool. `delete_many` découpe par lots de 1 000 (plafond de `delete_objects`).

`app/resources/` : bibliothèque **indépendante des blocs** (une ressource existe sans bloc). Flow en trois temps : déclaration (ligne `pending`, clé `courses/<course_id>/resources/<resource_id>/<nom-sanitizé>`, URL présignée PUT) → PUT navigateur → confirmation (HEAD S3 : objet absent ou taille différente → 409 ; statut `available`). Renommer ne change que le nom affiché (la clé S3 reste figée, le `Content-Disposition` suit). `download_url_for` partage la règle 409 + presign entre le régime prof et le régime public (`?disposition=inline` pour un affichage navigateur — c'est ce que résout la route front de redirection des liens de PDF exportés). Partager un cours expose **toute** sa bibliothèque `available`, blocs ou pas (assumé, averti dans l'UI).

Dev : MinIO dans le compose (job `minio-createbucket`). Une URL présignée mintée par l'API en conteneur pointe `minio:9000`, injoignable par le navigateur : tester l'upload avec uvicorn en local (`config/development.yaml` → `localhost:9000`).

## Modules interactifs

`app/modules/` : CRUD pur base d'une bibliothèque par cours, indépendante des blocs. Le code HTML/CSS/JS vit en colonnes `Text` (plafond `MAX_CODE_LENGTH` par champ), servi uniquement en JSON authentifié ou, côté élève, module par module sous `/public/courses/{id}/modules/{id}` — l'exécution est côté front en iframe sandbox à origine opaque sans réseau (cf. `docs/decisions.md`). La liste est légère (jamais le code) ; l'édition est partielle (`null` rejeté : vider un code = `""`). Au PATCH, `updated_at` du module est posé côté Python (le `onupdate` SQL ne tirerait qu'au flush, après la construction de la réponse).

## Export/import de cours

`app/course_transfer/` — seule exception à « pas de binaire par le backend ». **Export** (`export.py`) : `manifest.json` versionné (`format_version` 2, schémas `extra="forbid"`) en DEFLATE + une entrée `resources/<uuid>` par ressource `available` en STORE, assemblé en un `run_in_threadpool` dans un `SpooledTemporaryFile` (jamais une archive entière en RAM), fermé en `BackgroundTask` après l'envoi. Non exportés : propriétaire, visibilité, liens de partage, statut, `s3_key`, ressources `pending`. Matières/niveaux voyagent par leur `code`.

**Import** (`importer.py`) : recrée **toujours** un nouveau cours — uuid régénérés partout, colonnes `resource_id`/`module_id` remappées **et** références `oc-resource:`/`oc-module:` réécrites dans le markdown (`archive.rewrite_refs` ; référence inconnue laissée verbatim), ids de questions conservés, `visibility='draft'`, codes de taxonomie inconnus ignorés. Les archives v1 (manifest en nomenclature française) sont traduites par le normaliseur pur `normalize_manifest_v1` (`schemas.py`, dette de compat). Sécurité : seuls `manifest.json` et les entrées déclarées sont lues (jamais `namelist()`), tailles vérifiées deux fois (`file_size` du zip et compteur au flux décompressé), plafonds 413/`S3_MAX_UPLOAD_BYTES`/comptages, 422 pour tout manifest invalide. **Ordre transactionnel : inserts sans commit → put S3 → commit** ; un échec S3 → rollback + purge best-effort des clés poussées → 503. Le routeur est monté **avant** `courses` (le littéral `/courses/import` doit primer). Le plafond dur du corps HTTP relève du nginx d'infra (Starlette spoole le multipart sur disque).

## Régime public élèves

`app/public/` — `APIRouter(prefix="/public")`, **aucune dépendance JWT**. L'autorisation (`access.py`) : `get_public_course(db, course_id, token)` — cours `draft` ou inconnu → 404 ; `public` → passe, token ignoré ; `private` → exige un lien **scopé au cours**, non révoqué, non expiré — et `get_course_for_token(db, token)` pour l'entrée `/shared/{token}` (le lien d'abord, puis son cours ; `draft` → 404 même avec un lien valide). Validité vérifiée en Python (testable sur la fausse session). **404 uniforme** partout : un 410 serait un oracle. Seule exception : le 409 d'une ressource `pending`, où l'on est déjà autorisé sur le cours.

Le détail public (`service.py`) embarque les deux bibliothèques du cours (ressources `available`, modules en titres seuls) — le front y adosse ses onglets et sa résolution des `oc-resource:` ; le code d'un module reste servi module par module. `public_content` **reconstruit** le JSONB des exercices sans `expected_answer` (structurel, jamais un `exclude`) ; jamais de `s3_key`, d'`owner_id` ni d'e-mail (règle d'or de `schemas.py`). Le catalogue d'un prof (`/professors/{id}/courses`) rend la même réponse pour un utilisateur inconnu et un prof sans cours public.

`share_links` : token opaque 256 bits (`secrets.token_urlsafe(32)`) stocké en clair (capability URL recopiable), `expires_at` obligatoire (`SHARE_LINK_TTL_DAYS`, 270 j), révocation soft ; `draft` suspend les liens sans les toucher. Le token voyage en query param (CORS inchangé ; il apparaît dans les access logs — acceptable pour une URL volontairement diffusable).

## Recherche FTS

`app/search/` — même régime sans JWT. Config `french_unaccent` (extension contrib `unaccent` + copie de `french`, seule extension admise), `websearch_to_tsquery` (syntaxe libre, injection-safe, `q` blanc neutralisé). Deux vecteurs **stockés** (`courses.search_vector` titre A / description B ; `blocks.search_vector` titre B / contenu C, champ par champ, jamais `expected_answer`) maintenus par triggers et **combinés à la requête** (cours OU un de ses blocs via `EXISTS`, rang = `ts_rank(cours) + 0.5 × max(ts_rank(blocs))`), jamais consolidés (un trigger d'agrégation recalculerait tout le cours à chaque autosave). Profs : `searchable AND public_name IS NOT NULL AND EXISTS(cours public)`, vecteur calculé à la volée (table minuscule). Facettes : matière = sous-arbre via `Subject.code` (`= X OR LIKE X || '.%'`, deux petits selects) ; niveau = nœud + enfants directs. Une facette inconnue ⇒ page vide, jamais 422 (une URL partagée périmée reste servable). Enveloppe paginée de référence `{items, total, limit, offset}`.

Tests sans Postgres : les builders purs de `queries.py` sont validés sur leur **SQL compilé** (`compile(dialect=postgresql.dialect())`, config en bind param), plus un garde-fou textuel qui scanne les corps `$$…$$` des `blocks_tsvector` de toutes les migrations (ni `expected_answer` ni l'ancienne clé `reponse_attendue`).

## Client IA

`app/core/ai/` — client multi-provider **stateless** sur LangChain 1.x, approche BYO token. Seul paquet autorisé à importer `langchain*`, `langgraph`, `langfuse` (imports paresseux : rien n'est chargé au boot). La config (`AIRequestConfig` : provider, `api_key` en `SecretStr`, modèle, base_url) voyage à chaque appel ; `resolve_config` replie sur le fallback serveur `AI_*` (422 si aucun). Providers (`providers.py`, instanciation directe des classes `Chat*`, jamais `init_chat_model`) : anthropic, openai, google, mistral, ollama (base_url optionnelle), openai_compatible (base_url requise : Groq, vLLM, LM Studio…), huggingface (toujours `HuggingFaceEndpoint`).

Trois modes : `complete()` (réponse complète), `stream()` et `stream_agent()` — **méthodes sync à validation eager** : config résolue, chat model et graphe construits avant de retourner l'async generator, pour qu'une config invalide donne un vrai 4xx et non une erreur en plein flux. Erreurs traduites au bord (`errors.py`, duck-typing des SDK) : validation locale → 422 ; clé refusée → **400** (jamais 401, réservé au JWT) ; autre 4xx → 422 neutre ; 429 → 429 ; injoignable/5xx → 503 ; jamais le message brut du SDK.

**Agent** (`agent.py`) : `create_agent` de langchain sur des tools neutres (`AIToolSpec` = JSON Schema OpenAI, enrobés en `StructuredTool` async — aucun type langchain ne franchit la frontière). L'exécuteur ne lève jamais (`is_error=True` relayé au modèle en `ToolMessage` d'erreur ; exception imprévue → échec générique sans fuite). L'id réel de l'appel arrive à l'exécuteur par **contextvar** (LangChain ne peut pas l'injecter dans un args_schema) — clé d'appariement HITL. Plafond de rounds par `ModelCallLimitMiddleware` (avertissement français injecté, message anglais filtré par nœud). Les événements `tool_call` sont émis depuis l'update du nœud modèle (avant l'exécution), `tool_result` porte le contenu complet pour la persistance. **Images d'outils** : une `AIToolImage` voyage en artefact du `ToolMessage` puis est montrée dans un message utilisateur marqué (seule forme acceptée par tous les providers à vision), réordonné avant chaque appel modèle (`_hoist_tool_images` : résultats d'outils contigus, exigence OpenAI/Anthropic).

**HITL** : avec un `thread_id`, le run est checkpointé (`InMemorySaver` du client, process-local) ; `agent_interrupt(payload)` depuis un exécuteur fige le run — le flux émet `interrupt` (clé `__interrupt__` en mode `updates`, un tuple) et se termine sans `done` ; la reprise est un nouvel appel `stream_agent(thread_id=, resume=)` (messages ignorés, graphe rebâti avec les mêmes tools) : le nœud interrompu se ré-exécute depuis le début. Le filet d'exceptions re-lève `GraphBubbleUp` (signal de contrôle, pas une erreur). `GenericFakeChatModel` ne sait ni `bind_tools` ni streamer des tool calls : les tests agent utilisent le fake maison `SeqToolModel`.

**Langfuse** (`observability.py`) : actif ssi les trois `LANGFUSE_*` sont posés, sinon no-op sans importer le SDK ; trace rattachée au `sub`, jamais l'e-mail ; flush au shutdown. `model_catalog.py` liste les modèles d'un provider par REST direct (LangChain n'a pas de « list models » uniforme ; clé en header, jamais en URL).

`app/core/sse.py` porte le contrat SSE de référence (`token`/`thinking`/`done`/`error`, JSON compact, `\n\n`, flux clos après `done`/`error`, l'événement `error` portant le status « qu'aurait eu » la requête) ; `app/ai/` en est le banc d'essai.

## Credentials IA et quota

`app/ai_credentials/` + `app/core/crypto.py`. Un credential par utilisateur (colonnes `users.ai_*`, CHECKs de cohérence à la main ; règles par provider en 422 service). Clé chiffrée : AES-256-GCM, clé dérivée HKDF-SHA256 de la clé maître `AI_CREDENTIALS_MASTER_KEY` avec un **sel par utilisateur** régénéré à chaque écriture, blob versionné `0x01 || nonce || ciphertext+tag`. Portée : un dump DB seul ou le seul `.env` sont inexploitables ; un serveur compromis peut déchiffrer (inhérent). La clé, chiffrée ou non, ne figure dans **aucun** schéma de réponse (`api_key_set: bool`) ; `api_key` omise au PUT = clé conservée. Deux sondes POST BYO token intégral (test de connexion sans `max_tokens` — un plafond minuscule fait échouer les modèles « thinking » ; liste des modèles), jamais de quota ni d'écriture.

**Cascade** `effective_config(db, auth, explicit)` : explicite > credential (illisible ⇒ 422 « ré-enregistrez », jamais un repli silencieux) > fallback `AI_*`. Seul le fallback est **compté** : quota quotidien par utilisateur (`users.ai_daily_call_quota`, NULL = `AI_DEFAULT_DAILY_QUOTA`, 0 = illimité mais compté ; sans CHECK, jamais écrit par une route — l'opérateur le pose en SQL). Table `ai_daily_usage` (PK `(user_id, day)` UTC), **upsert atomique** plafond-en-WHERE (rowcount 0 = 429, avant tout appel provider). Sémantique réservation + remboursement : consommé avant l'appel, remboursé si le provider échoue (`QuotaTicket` capturant le jour — un échec peut traverser minuit ; `refund_on_error` pour les échecs eager, l'encodeur de tour avant le premier token ; un flux qui a produit du contenu reste compté). Le remboursement est best-effort : ne jamais masquer l'erreur d'origine.

## Assistant IA de cours

`app/course_assistant/` — chat du prof par cours, conversations persistées par contexte (`course`, `block_text`, `block_exercise`, `module`).

**Modèle** (`ai_conversations`, `ai_messages`) : la conversation porte le contexte et sa cible (`block_id` ou `module_id`, CHECK de cohérence), `updated_at` bumpé côté Python à chaque message. Trois rôles ; les **tours `tool` sont persistés** (`tool_call_id` apparié, `is_error`), les segments `assistant` portent `tool_calls` (données de replay) et `provider` (les ids de tool call ne sont pas interchangeables entre providers) ; le segment final porte `sources` validées et l'usage. Le thinking n'est jamais persisté.

**Références courtes** (`refs.py`) : les modèles déforment les UUID recopiés. `build_refs` numérote l'instantané (`B1…`, `R1…`, `M1…`, et `Q1…` pour les questions du bloc édité) ; prompt, tools (`enum` par tour) et citations n'utilisent que ces références ; `CourseRefs.resolve` est tolérant (référence, UUID exact, plus long préfixe commun ≥ 8 hex, titre exact ou approchant) et liste les candidats en cas d'échec ; `CitationRewriter` réécrit `oc-block:B3`/`oc-resource:R2` en UUID **en flux** (retenue minimale d'un suffixe pouvant amorcer une citation) — texte streamé = texte persisté, contrat SSE et front inchangés. `extract_sources` filtre les ids hallucinés.

**Contexte** (`context.py`, `render.py`, `replay.py`) : system prompt assemblé par fragments (`prompts.py`) + cours en markdown avec références (corrigés inclus : c'est le prof) + bibliothèques ; plafond de 60 000 caractères (heuristique) puis **mode sommaire** (extraits + invite `read_block`) ; en contexte d'édition la cible est rendue en entier même en mode sommaire. Replay des 30 derniers messages sans couper un round ; un round d'un autre provider ou incomplet est replié en texte.

**Tools de lecture** (`tools.py`) : `read_block`, `read_resource_pdf` (pypdf sous un `run_in_threadpool`, plafonds taille/pages/caractères), `read_resource_image` (png/jpeg/gif/webp, plafond brut ≈ 3,5 Mo ; image jointe pour ce tour seulement, jamais rejouée), `read_module`. Aucun accès DB pendant l'exécution.

**Flux** (`streaming.py`, `turn_encoder.py`) : ownership → conversation → messages → cascade → instantané (`load_snapshot`) → insert du message user + commit **avant** l'appel provider → `stream_agent`. L'encodeur de tour (partagé avec le tuteur) tient la boucle SSE, la réécriture des citations, l'ordre d'émission (le texte retenu part avant tout événement non-token), les extraits de `tool_result` (400 caractères, même valeur côté front — le contenu complet est servi par le détail de conversation) et le remboursement avant premier token ; le sink `_AssistantTurn` persiste les segments à la clôture. `done` porte les ids persistés (le front réconcilie sans refetch).

**Contextes d'édition** (`editing/`) : un contexte = un descripteur `EditContext` (cible bloc ou module, type de bloc attendu, system prompt, tools de proposition avec spec, validation et réécriture des args) enregistré dans `EDIT_CONTEXTS` — aucune branche par contexte ailleurs (seul aiguillage : la cible, `_check_edit_target`/`_resolve_focus`). Ajouter un contexte = un module sous `editing/`, une entrée au registre, le `Literal` de `ConversationCreate`. `hitl_gate` (`editing/base.py`) est le seul appelant d'`agent_interrupt` : à appeler après validation (le tool est ré-exécuté à la reprise), il fige le run et, à la reprise, retourne le texte de décision. Granularité : texte = markdown intégral (`propose_block_edit`) ; exercice = une opération par question (sujet, énoncé/corrigé, ajout, suppression ; références `Q…` **stables le temps d'un tour**, capturées à l'interrupt et rejouées) ; module = un fichier (`propose_html_edit`/`css`/`js`, args identité). Les plafonds sont appliqués en validation, jamais en `maxLength` de schéma (support inégal des providers).

**Mécanique HITL** : à l'interrupt, le tour partiel est persisté (segment porteur du `tool_call`, sans ligne `tool` — un abandon reste un round incomplet replié au replay), la reprise est enregistrée au registre in-process (`hitl.py` : thread, appel, config résolue, `question_refs`, TTL 6 h), le flux émet `interrupt` et **se ferme sans `done`**. La décision (`POST …/proposals/{tool_call_id}/decision`) rouvre un flux qui reprend le run avec la **même config** (pas de nouvelle cascade ni de quota : un tour HITL = un appel compté) — le résultat du tool est la décision ; un nouveau message abandonne la reprise. La route de décision ne mute jamais le bloc : c'est le front qui applique, puis flush son autosave avant chaque décision (la reprise relit la cible en base). Le registre et le checkpointer sont process-locaux ⇒ mono-worker (TODO.md).

## Tuteur d'exercice élève

`app/student_exercises/` — sous `/student/courses/{id}/blocks/{id}/…`, **JWT requis** mais accès au cours par `get_public_course` (visibilité + `?token=`). L'élève soumet, question par question, une réponse (`kind=answer`) ou un message (`kind=message`) ; chaque tour est une ligne `exercise_submissions` (`question_id` = id JSONB, stable ; FK CASCADE user/cours/bloc ; index du fil `(user_id, block_id, question_id, created_at)`), insérée avant l'appel provider et complétée à la clôture (`feedback`, `verdict`, `effort`, `revealed`, usage). Le corrigé n'est jamais copié en table : la lecture du fil le relit dans le bloc ssi un tour l'a révélé.

**Redaction structurelle** : l'instantané des blocs passé au modèle et à ses tools de lecture est produit par `public_content` (aucun `expected_answer`), seul le corrigé de la question cible est joint au prompt (section confidentielle). **Verdict structuré** : le modèle appelle `record_verdict {verdict, effort, reveal}` avant d'écrire ; `guard_reveal` côté serveur n'honore `reveal` que si la réponse est juste ou l'effort suffisant ; sans appel du tool, rien n'est révélé ; le corrigé n'est joint au `done` que si `revealed`. Le tuteur tutoie, renvoie au cours par citations `oc-block:` et ne donne jamais la réponse. Effacement : l'élève efface ses tours (bloc ou question), le prof ceux de tous ses élèves depuis l'éditeur (résumé par question + DELETE, `teacher_router` du même paquet). Risque assumé : un modèle faible peut paraphraser le corrigé qu'il voit (TODO.md).

## Purge périodique

`app/maintenance/` — un **job**, pas une route : service compose `purge` (même image, boucle shell `python -m app.maintenance` puis `sleep PURGE_INTERVAL_SECONDS`, lue une fois au démarrage avec repli sur 86400 ; entrypoint écrasé pour ne pas rejouer les migrations, qui restent le job du seul service `api`) ; sous le profil `maintenance` en dev, présent dans le compose de preprod (sinon `--remove-orphans` le détruit à chaque déploiement). Une passe part à chaque démarrage du conteneur (vérifiable dans les logs sans attendre 24 h). Ne pas le remettre dans le process uvicorn : la réconciliation S3 énumère tout le bucket.

**Garde de schéma** (`schema.py`) : `depends_on: service_healthy` n'ordonne que la première mise en route et ne protège ni du reboot du Pi (`restart: unless-stopped` repart sans réévaluer les dépendances) ni d'un déploiement portant une migration alors que ce conteneur tourne déjà. D'où le renversement : avant d'écrire, le job compare la révision `alembic_version` à la tête du dossier `alembic/` de son image (`Config()` en mémoire, `script_location` absolu) ; tant qu'elles diffèrent il attend (poll 5 s, 5 min) puis **renonce à la passe** (exit 1, la boucle réessaiera). Base jamais migrée et rollback vers une image plus ancienne sont gérés. Principe : ne rien purger est toujours sûr.

**Sept tâches** (`service.py`, réglages `PURGE_*` dans `config/*.yaml`, `0` = désactivée, défauts prudents), borne calculée en Python (`datetime.now(UTC)`, jamais le `now()` de Postgres qui suit le fuseau du serveur), une transaction par tâche, échec isolé et journalisé : usage IA quotidien (365 j, **plancher 2 jours** : le jour courant porte le quota vivant et un remboursement peut viser la veille) ; contenu des tours `tool` (180 j — le plus gros gain disque : `UPDATE` jamais `DELETE`, la ligne doit rester appariée ; on garde 400 caractères = l'extrait déjà affiché + un marqueur ; idempotent par arithmétique) ; conversations IA (désactivée) ; tentatives d'élèves (désactivée — données personnelles) ; liens de partage expirés (365 j, sur `expires_at` seul — un lien révoqué non expiré est conservé comme trace) ; ressources `pending` (30 j, purge S3 après commit) ; **réconciliation des orphelins S3** (grâce 90 j, `dry_run` par défaut ; balaye `courses/` et `users/` page par page avec une anti-jointure contre `resources.s3_key` et `users.avatar_s3_key` ; la grâce est une sécurité : l'import pousse ses objets avant son commit et un upload vit entre presign et confirmation). Tests sur SQL compilé + faux S3 partageant une liste d'événements prouvant que la purge du bucket suit le commit.
