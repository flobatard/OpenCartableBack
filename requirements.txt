# Dépendances de l'API — VERSIONS EXACTES.
#
# Pourquoi des pins et pas des fourchettes : le Dockerfile fait un
# `pip install -r requirements.txt` AU BUILD. Avec des fourchettes, l'image de
# préprod reçoit ce qui est le plus récent le jour du build, pas ce qui tourne
# en dev — dérive constatée sur langchain-google-genai, dont le registre de
# profils de modèles avait changé entre les deux (options de raisonnement
# fantaisistes proposées pour Gemini 2.0 ; cf. docs/decisions.md, décision 24).
#
# Mise à jour : `pip install -U <paquet>` dans le venv, `pytest` + `ruff check`,
# puis reporter ici la version obtenue (`pip show <paquet>`).
#
# Pas de lock complet (transitives figées par `pip freeze`) : sur x86 la pile
# ML tire des wheels nvidia/cuda qui n'existent pas en ARM64, un tel fichier
# casserait le build de l'image du Raspberry Pi. Les pins portent donc sur les
# dépendances DIRECTES — les paquets partenaires du client IA, seuls à porter
# des données qui changent le comportement, en font tous partie.
